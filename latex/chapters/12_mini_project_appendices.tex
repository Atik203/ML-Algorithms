\chapter*{Integrated Mini Project: Comparative Machine Learning Study}
\phantomsection
\addcontentsline{toc}{chapter}{Integrated Mini Project: Comparative Machine Learning Study}
\label{exp:mini}
\runninghead{Integrated Mini Project}

\quickfacts
  {Scope}{Compare algorithms from different families on identical data, splits and seeds}
  {Protocol}{Fixed random seeds; untouched test sets; two or more metrics per task}
  {Headline result}{Gradient boosting leads tabular regression; ensembles tie on small classification data; density clustering finds real seismic zones without labels}

\section{Objective}
For the final laboratory assessment, compare at least three algorithms from different
families on one real-world dataset, with a controlled, explainable experiment rather than a
search for the largest score.

\section{Suggested Dataset}
The manual's own experiments provide the comparison material: Heart Disease (classification),
California Housing (regression), Mall Customers (clustering) and the USGS earthquake
catalogue (density-based clustering).

\section{Required Libraries}
scikit-learn, xgboost, catboost, numpy, pandas, matplotlib.

\section{Workflow}
\begin{enumerate}
  \item Define a specific prediction or clustering problem.
  \item Identify the target variable (supervised) or justify the absence of labels.
  \item Inspect missing values, duplicates, class balance and feature types.
  \item Create a train/test split before fitting preprocessing steps that learn from data.
  \item Build a simple baseline.
  \item Train at least three candidate algorithms from different families.
  \item Use cross-validation on the training data for model selection where appropriate.
  \item Evaluate once on the untouched test set.
  \item Analyze errors, not only aggregate metrics.
  \item Document limitations, reproducibility settings and possible future improvements.
\end{enumerate}

\section{Discussion and Conclusions}
\begin{enumerate}
  \item On small tabular classification, simple boosting (AdaBoost) or bagging (RFC) match the
        heavier models; differences are within noise for 76 test samples.
  \item On larger regression data, gradient boosting clearly wins ($R^2 \approx 0.80$ vs.\
        0.74 for random forests and 0.59 for AdaBoost).
  \item Clustering algorithms agree on well-separated data (silhouette $\approx 0.55$);
        density methods are the only option for arbitrary shapes and noise, and their clusters
        match real seismic zones without labels.
  \item Sequence models confirm the expected ranking: LSTM $>$ vanilla RNN, with the largest
        gap on the task that needs long-range memory.
  \item Fair comparison requires identical splits, fixed seeds, untouched test sets and at
        least two metrics per task; no test-set model selection was performed.
\end{enumerate}

\section{Common Experimental Mistakes to Avoid}
\begin{itemize}
  \item Scaling the entire dataset before the train/test split, which can leak test-set information.
  \item Selecting hyperparameters using the test set repeatedly.
  \item Comparing models on different train/test partitions.
  \item Reporting only accuracy on imbalanced classification problems.
  \item Treating cluster labels as ground truth without understanding the evaluation method.
  \item Changing several hyperparameters at once without recording the experiment.
  \item Using private or sensitive data in external LLM services.
  \item Claiming causation from feature importance or correlation alone.
  \item Copying library output without explaining the underlying algorithm.
\end{itemize}

\section{Viva / Discussion Questions}
\begin{enumerate}
  \item \textbf{Which model performed best overall?}\par\nobreak It is task-dependent: AdaBoost/RFC on small
  classification, XGBoost/CatBoost on tabular regression, LSTM for sequences, RBF SVC for
  small high-dimensional classification and GRNN for smooth low-dimensional regression.
  \item \textbf{Why not select the model by its test score?}\par\nobreak That leaks the test set into model
  selection; candidates should be compared on validation data and evaluated once on the test
  set.
  \item \textbf{Why report more than one metric?}\par\nobreak Each metric captures a different failure mode:
  accuracy hides class imbalance, RMSE weights outliers more than MAE, and silhouette favours
  compact convex clusters.
  \item \textbf{How is reproducibility ensured?}\par\nobreak Fixed seeds everywhere, committed datasets, documented
  preprocessing and splits, and complete code listings for every experiment.
\item \textbf{How would you detect data leakage in a comparison like this?}\par\nobreak Check that every preprocessing step that learns from data (scaling, encoding, feature selection) is fitted on the training split only, and that model selection never touches the test set.
\end{enumerate}

\chapter*{Appendix B: Reproducibility Checklist}
\phantomsection
\addcontentsline{toc}{chapter}{Appendix B: Reproducibility Checklist}
\runninghead{Appendix B: Reproducibility Checklist}

\begin{itemize}
  \item Python version recorded.
  \item Package versions recorded.
  \item Random seed recorded where supported (all experiments use seed 42).
  \item Dataset source and version recorded (public datasets committed under \texttt{data/}).
  \item Preprocessing steps recorded (scaling fitted on training data only; haversine radians for geospatial data).
  \item Train/validation/test protocol recorded (stratified, chronological, early-stopping split, 5-fold CV).
  \item Hyperparameters recorded.
  \item Evaluation metrics defined before final testing.
  \item Plots and tables saved with meaningful names.
  \item Code runs from a clean environment or requirements file.
\end{itemize}
